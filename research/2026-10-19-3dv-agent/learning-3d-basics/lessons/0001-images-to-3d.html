从照片到三维模型

第一课：看懂 reconstruction pipeline、三类主要错误，以及 benchmark 在测什么。预计 8 分钟。

今天只记一个式子：三维重建 = 每张照片从哪里拍（camera pose） + 每个像素有多远（depth） + 如何把各张结果合起来（fusion）。

1. 为什么一张照片不够？

照片把三维世界压扁成二维。同一个像素可能来自近处的小物体，也可能来自远处的大物体。换一个位置再拍，物体在两张图中的移动量不同；这种视差提供距离信息。COLMAP 把传统过程分成特征提取、匹配与几何验证、结构和相机恢复，之后再做稠密重建。

多张 RGB同一场景，不同视角
对应关系哪些像素是同一点
相机 pose每张图从哪里拍
depth / point map每个像素在哪里
融合几何点云、表面或 mesh

2. 三类错误看起来有什么不同？

点击按钮。虚线表示另一张视图认为表面应该在的位置。

正常：相机位置、局部深度和融合互相一致，两张照片支持同一个表面。

3. 传统方法和现代模型差在哪里？

传统 COLMAP / SfM + MVSVGGT / DA3 / π³-X
做法先匹配特征，再解相机和稀疏点，最后估计稠密表面。神经网络一次或少数几步直接预测相机、depth 或 point map。
优势几何约束明确，过程可检查。快，弱纹理时可借助学习到的先验。
风险匹配失败会让流程断掉。可能输出看似合理但跨视图不一致的几何。

4. Benchmark 指标到底在问什么？

指标它问的问题陷阱
Pose error / AUC预测的相机相对位置和朝向是否正确？AUC 通常越高越好。相机正确不代表表面正确。
Accuracy你预测出来的点，有多少靠近真实表面？只预测少数最安全的点也可能很准。
Completeness真实表面有多少被你的预测覆盖？撒很多噪声点可能提高覆盖。
F-score同时兼顾 accuracy 和 completeness。仍然需要结合误差图看失败位置。

5. 这和我们的 paper 有什么关系？

我们已经看到一种关键情况：DA3 的相机是四个模型里最好的，但几何仍然输掉。对 ScanNet++ 的 8 个这类场景做受控替换后，最大的改善全部来自 depth。于是“看到总分差就修 camera”是错误策略。

我们真正想测试的是：几何 residual 先指出“这里不一致”，VLM 再看 RGB 和局部状态，判断这是相机错、depth 错、融合错，还是不该采取动作。VLM 只有在相同工具和预算下超过 support-aware 数值规则，才有论文价值。

30 秒自测

相机 AUC 很高，但 F-score 很低。最合理的第一反应是什么？

正确：先检查 depth 与 fusion。相机指标只覆盖 camera，并不证明表面正确。
