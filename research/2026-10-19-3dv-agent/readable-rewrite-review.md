# RW survey：已有方法能修到哪一步

固定照片的三维重建｜证据与待验证问题

我们研究的是：给定同一组照片，能否用不额外训练的 agent，把现有模型估计的相机位置和三维表面修得更好。先看 benchmark 和已有失败证据，再决定需要开发什么工具。

先看一个真实例子：VGGT-Ω 论文图6展示，DA3 在重复雪地纹理的视频中几乎没有预测出相机运动；另一个航拍例子重建出重复塔楼。Ω 改善了这些结果 [S5]。这说明错误存在，也说明换更强的几何模型就能解决一部分；两个例子并未标为我们五套 benchmark 的场景。

## 1. Benchmark 已经告诉我们什么

采用 DA3 发布的五套评测子集：DTU 看物体表面，ETH3D 看真实室内外，ScanNet++ 看复杂室内，7Scenes 看手持室内序列，HiRoom 看合成室内。统一输入和评测代码，避免把不同论文的分数直接拼成排行榜 [S1]。

| 数据 / 证据 | 已有结果说明什么 |
| --- | --- |
| DTU：π³ 表6 [S2] | 更换参考帧会影响 VGGT 的结果，π³ 已明显减轻这种敏感性。 |
| ETH3D：GLUEMAP 表1 [S3] | π³ 的相机 AUC@3°：36.1；加 BA 后55.1；GLUEMAP 为76.9。证明相机优化有效，未直接证明表面更准。 |
| ETH3D / ScanNet++：GGPT [S4][S4b] | 有修复前后误差图；ETH3D 八视图中，VGGT 点图 AUC@5cm 从23到47，是完整修复流程的收益。 |
| 7Scenes / HiRoom：DA3 发布结果 [S1] | 给定真值相机时分数更高，但不能据此断言错误来自模糊、材质或匹配。 |

特别注意：给 DA3 真值相机，还会改变深度预测和尺度处理。因此两种模式的分数差，不能当成“只修相机就能获得的提升” [S9]。现有材料也没有给出覆盖这五套数据、逐场景标注错误原因的完整清单。

## 2. Related work 分成三类看

直接重建：VGGT（CVPR 2025）、VGGT-Ω（CVPR 2026）、π³-X（2025年12月工程更新）、MapAnything（3DV 2026）、DA3（ICLR 2026），从照片预测相机、深度或三维点。它们决定我们应该超过什么水平。

几何修复：MP-SfM、GLUEMAP 改善相机估计；GGPT 用照片得到的稀疏几何约束修正稠密点云。它们说明“重建后再修一次”已有有效方法，必须直接比较 [S3][S4][S10]。

## 3. 哪些问题值得我们修

Agent 相关：AREA3D 通过获取新视角改善重建；GRASE 修复可编辑的仿真场景。我们使用固定照片，评价相机和真实场景几何。但“检查—调用工具—修复”本身不能作为新的技术贡献。

| 值得检查的错误 | 已有修复与 VLM 可能的增量 |
| --- | --- |
| 相机位置不准，多个视图拼不齐 | BA / GLUEMAP 已能优化。开发可回退的相机重估工具；VLM 必须比几何指标更会选择修复目标。 |
| 相机大致对齐，但表面重影或错形 | GGPT 已有修复证据。开发引导质量检查和几何修复接口；VLM 利用边界与可见性定位疑点的收益待测。 |
| 相似物体被当成同一个 | Ω 与 DG++ 有案例 [S5][S6]，尚非五套数据的普查。仅在开发集确认后接入图像对验证；VLM 的实例判断须超过已有分类器和几何验证。 |

暂不优先做：π³ 已明显减轻参考帧依赖，π³-X 已改进网格伪影与置信度 [S7]。透明物体是 π³ 报告的局限，但尚无对应五套测试集的发生率与成功修复证据；识别玻璃后删掉点，并不等于恢复了玻璃的几何。

## 4. 我们只验证一个核心问题

同样的照片、初始重建和工具，VLM 看原图与几何状态，能否更合理地决定修哪里、调用什么，以及修完后继续还是撤销？现有论文支持“工具能改善重建”，尚未证明“VLM 比几何规则更会选择工具”。

因此必须比较：直接重建、强固定修复，以及相同工具下的固定顺序、几何选择器、一次性 VLM 计划、多步 VLM、去掉图像的多步 VLM。只有后几项比较，才能把工具收益、看图收益和执行反馈收益分开。

当前定位是 training-free 的重建修复系统；模型权重冻结，允许场景内几何优化。VLM 的作用仍是假设，不预先声称它理解了错误。具体实验见“实验计划”标签页。

# 实验计划：怎么证明 Agent 有用

与 RW survey 配套｜尚未运行实验

只回答两个问题：能否修好现有模型的重建？同样的工具交给 VLM 根据图像和反馈来调用，是否比固定流程更有效？不训练或微调模型，允许优化当前场景的相机和三维点。

## 1. 输入、数据与输出

输入固定的一组 RGB 照片；输出每张照片的相机位置和朝向，以及场景的三维表面。先跑一个现成模型得到初始重建，再让 agent 修复。初始主干只选一个，不要求同时调度所有 baseline。

| 数据与本次规模 | 看什么 |
| --- | --- |
| DTU：几何22场景×49视图；位姿13×64 | 受控物体的表面与相机；两项使用不同样本。 |
| ETH3D：11场景 | 真实室内外的对齐与几何。 |
| ScanNet++：20场景 | 复杂室内的表面与相机。 |
| 7Scenes：7场景；HiRoom：24场景 | 手持室内与合成室内；分别报告结果。 |

沿用 DA3 发布子集及评测代码 [S1]，并非五个完整官方榜单。先在不重合的 ScanNet++ training 场景开发工具，核对并保存场景清单；测试前冻结工具、参数和预算。测试真值只给评估器，不能用于选动作或选最终结果。

## 2. 用墙面重影解释 Workflow

以下是假想示例，不是已跑出的结果：同一面墙被重建成两层，可能是几张照片的相机位置估错，也可能是局部深度错了。看见重影并不能直接确定原因。

先检查：给 agent 原图、匹配叠图、相机与点云视图，以及跨视图不一致的位置。它提出目标视图或区域、调用的工具和预期变化；不直接编造三维坐标。

再尝试修复：相机工具用 BA / GLUEMAP 重新估计并更新下游几何；表面工具用 GGPT 和照片得到的稀疏约束修正三维点。局部重估与重融合仍需开发验证；相似物体误关联只有在开发集确认后才增加验证工具。

最后看反馈：执行后检查一致性和覆盖，保留、撤销或继续；预算耗尽或无需继续时停止。每步留快照，原始结果也可保留。删除困难表面会降低完整度，不能把少了点当成修好了。

## 3. Baseline 分三类比较

第一类：现成重建模型。回答“直接用现在的模型能做到什么程度？”

| 模型 | 大概是什么 |
| --- | --- |
| VGGT / VGGT-Ω | 从照片预测相机、深度和三维点；Ω 是后续版本，避免只修旧模型的问题。 |
| π³-X | π³ 的工程增强版；π³ 减轻对指定参考图像的依赖。 |
| MapAnything / DA3 | 通用重建 / 多视图深度与相机模型；主比较均只给 RGB。 |

第二类：已有修复方法。BA 联合调整相机与三维点，让投影一致；GLUEMAP 改善相机对齐，再接 DA3 做表面重建；GGPT 用稀疏几何引导修正稠密点云。直接运行这些强流程，检查是否根本不需要 agent。同一方法可以既是工具，又是独立 baseline。

第三类：我们搭的控制实验。共享初始重建、工具和参数范围，检查决策方式带来什么变化。

| 怎么调同一套工具 | 它回答的问题 |
| --- | --- |
| 固定顺序；几何指标选择器 | 写好流水线或依据数值判断，是否已经够用？ |
| 一次性 VLM 计划；多步 VLM | 执行后重新检查、改计划，是否更有效？ |
| 多步 VLM 去掉图像 | 看原图和可视化，是否比只读数值更有用？ |

一次性计划也可调用多个工具，只是不再根据执行结果改计划；多步版本每轮可重选。无图像版本移除视觉输入，保留数值状态与日志。同硬件限制总 GPU 秒，计入 VLM 和失败尝试，另报墙钟时间与 token。

## 4. 怎样才算成功

同时看相机误差、表面准确度和完整度，以及耗时。沿用各数据集的对齐与指标：相机 AUC、几何 accuracy / completeness、DTU Overall 和适用的 F-score。完整评测预定场景，报告改善、退化与失败比例。

只超过原始模型，说明修复系统有用；超过强固定修复、几何选择器和一次性计划，才支持多步决策的价值；去掉图像后变差，才支持视觉输入的增量。工具带来的收益应归因于工具。

尚未定：初始主干、VLM、参数与预算。模型与修复 baseline 均按同输入重跑；Ω 拟用官方复现权重，访问尚未取得。开发时另做“固定深度只换相机”和“固定相机只改几何”的检查，避免把两者收益混为一谈。
