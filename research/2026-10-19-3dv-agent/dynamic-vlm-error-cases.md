# 动态、参考系与状态变化：VLM 诊断重建错误的候选案例

核查日期：2026-10-19。本文是原始论文核查与研究假设，不是实验结果；没有运行 pilot。以下案例特意对照已有 VLM 方法，避免把“识别动态对象并分割”误写成研究空白。

## 结论

**普通动态污染并不是值得主打的新 gap。** The Dynamic Prior（Dynapo，2025-12 首版）已经实现 VLM 视频推理、对象及关键帧选择、SAM2 分割，并将 mask 接入 BA、深度和轨迹优化。最近动态重建也不只会删除运动物体：Flow4R 支持参考系切换，SM4RT 显式恢复运动分量，FunREC 用 VLM 划分交互片段并选择关节类型。

剩余可能是“当前采用的运动/时间模型是否适合这次重建，以及几何反馈是否反驳最初语义判断”。但本次没有找到证据足以保证 VLM 比专门模型更适合，不能先定贡献再寻找例子。

## 1. 必须正面对照的最近工作

| 工作 | 已核实覆盖 | 对候选题的限制 |
|---|---|---|
| [RoMo，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/papers/Goli_RoMo_Robust_Motion_Segmentation_Improves_Structure_from_Motion_ICCV_2025_paper.pdf) | 光流、epipolar cues、预训练视频分割特征迭代结合，改善动态 SfM；作者明确报告低视差与缺乏可见静态背景时的限制 | 不能称现有方法只看几何、不会用语义；短暂停止运动也不是未处理的问题 |
| [Dynapo / The Dynamic Prior，2025-12](https://arxiv.org/html/2512.05398v1) | VLM 判断运动对象、遮挡及出现消失，选显著帧，输出对象描述，经 Sa2VA/SAM2 生成 masks；将 masks 接入现有 BA/深度/4D 优化 | “VLM 理解动态物体→调分割→修复 pose”已被直接做过；作者指出大动态物体占据视野时 filter-out 失败，同类多实例文本定位有歧义 |
| [Flow4R，ECCV 2026](https://arxiv.org/html/2602.14021v1) | 场景流与 pose weights 分解相机/物体运动；权重可替换以切换参考系；正文直接讨论扶梯引起的任务相关参考系选择 | “识别参考系问题”也不是全新问题；剩余至多是自动选择并验证参考系，不能把坐标变换本身当贡献 |
| [SM4RT，2026-07](https://arxiv.org/html/2607.22534v1) | 用 SE(3) motion bases 和跨时间分配表示结构化物体运动，单次前馈恢复几何与运动 | 多刚体和运动结构已有强非语言模型；VLM 不能只赢传统静态 COLMAP |
| [Contextual Semantic Mapping，2026-06](https://arxiv.org/html/2606.24814v2) | 多视角 VLM 判断对象类别及 immovable/movable/mobile；托盘在地上与在叉车上区别处理 | 情境化可移动性本身已有工作；实验是 18 实例、74 帧的受控场景，GMapping 从激光估姿，指标是语义/可移动性/全景分割，并未证明修复相机或重建 |
| [FunREC，CVPR 2026](https://arxiv.org/html/2604.05621v2) | RGB-D、已知内参；VLM 分静态/交互片段并预测旋转/平移关节，估相机、拟合运动、分割活动部件，融合静态和 canonical 动态 TSDF | “VLM 判断门在转动，选择铰链模型”已覆盖，且并非只接受已知相机位姿 |
| [SCaR-3D，2025-12](https://arxiv.org/html/2512.22830v1) | COLMAP 注册前后场景，多视角变化检测并选择性更新 3DGS；注册假定大多数特征不变 | 真实物体移动与局部更新并非空白；尚可讨论的是变化与错误注册互相混淆的情形，而不是一般变化检测 |

阅读深度：Dynapo、Flow4R、SM4RT、Contextual Mapping、FunREC、SCaR-3D 核查方法及实验/限制；RoMo 核查正式 CVF 正文及补充材料的相关段落。没有复现报告数字，不将论文自述推广为所有情形已解决。

## 2. 假设案例 A：旋转商品被当成应删除的动态干扰物

### 具体输入与错误

固定相机拍转台上的鞋/小家电，目标是得到商品模型；画面外围可见桌面、转台底座或手。普通 world-static SfM 可能只重建桌面；动态 mask 可能删除商品主体。也可能以主体为参考系恢复了有效的商品相对相机轨迹，却被错误解释为世界相机在运动。

这不是“几何永远解不出”，而是几何解与任务坐标系不一致。在没有静态参照时，从纯视觉无法把相机运动和物体运动唯一分开；VLM 不能消除不可观测性。

### VLM 实际需要看到什么

- 原视频的多帧及明确目标：商品重建还是室内地图。
- 主体/背景分区后的 tracks、各自刚体拟合残差、保留像素与 track 覆盖率。
- 当前 pose weights 或 motion components 在图像上的投影，及当前重建的主体覆盖情况。

可检验诊断是：“当前 pipeline 把用户目标对象当作动态 outlier 删除；应改为主体坐标系重建。外围桌面用于识别采集协议，不能同时强制为同一静态刚体。”

### 可执行修复

分割目标和转台/手，使用目标 tracks 估计相对相机位姿；或替换 Flow4R pose-weight map，以目标为参考；用同一后端重建目标。若目标本身发生形变，则这个刚体假设应被后续残差否定，而不是强制接受。

### 现有覆盖与仅剩增量

Flow4R 已支持上述参考系切换，物体中心重建也早已存在，Dynapo 已能识别运动对象。**可能增量仅是从任务、采集情境和失败状态自动诊断“删错了目标”，选择正确的模型/参考系，并验证。** 这是 VLM 可能擅长的语义—任务结合，但如果目标文字或用户框就足以决定参考系，多步 Agent 几乎没有必要。

### 可以推翻假设的对照

相同 masks/Flow4R/后端下比较：(1) 显式目标分割后固定 object-centric 重建；(2) 无语言多刚体估计+任务目标选择；(3) 一次性 VLM；(4) 看几何反馈的 VLM。若 (1) 或 (3) 与 (4) 相当，应放弃“Agent 诊断”主张。评测必须以正确任务参考系对齐，分别报告目标几何和世界相机位姿，不能把不同坐标定义当作 pose 改善。

## 3. 假设案例 B：柜门换了状态，却把局部变化“修”成全局相机漂移

### 具体输入与错误

扫描房间时，柜门前半段关着，后半段打开；或跨两次拍摄，同一柜门停留在不同状态。每一段内部都近似静态，跨段约束却把两个门面当同一静态表面。结果可能出现门面重影、墙体被拉歪或相机轨迹折弯。

数值残差能指出冲突，却不一定区分“相机错了”与“一个部件真的变了”。纯对象类别也不足够：柜体可静态，门叶可动；不同时间同一门叶应允许不同状态。但这不是纯几何不可能处理的问题：多刚体拟合、变化检测和关节模型已有方案。

### VLM 实际需要看到什么

- 变化前后带编号的门叶、门框、把手、墙面的多视角图像；避免只靠自由文本定位实例。
- tracks 按门叶/门框/墙面分组后的 residual；跨时段匹配与部件重影的投影。
- 分别保留墙面和门面约束得到的候选相机估计，以及部件运动是否符合一个稳定轴/平移方向的检验结果。

可检验诊断是：“错误由跨状态共享静态门叶约束造成；稳定门框和墙面仍可连接两段相机。”语义提出关节类型候选，实际轴与状态必须由几何拟合确定。仅看到一个把手不能证明门已经动过。

### 可执行修复

解除门叶跨状态的静态 track 绑定，保留稳定结构约束；按状态分组或拟合关节运动后重新优化相机；在 canonical 部件空间融合门叶。若任务只要静态背景，则直接排除运动期间的门叶，但要单独统计被牺牲的覆盖。

### 现有覆盖与仅剩增量

FunREC 已经做 VLM 时间切分、关节类型预测、几何拟合和静/动态重建；Articulate-Anything 已做 VLM actor-critic articulation。SCaR-3D 已做变化后局部更新。[Articulate-Anything 项目](https://articulate-anything.github.io/)

**可能剩余增量仅是：在已有错误重建中，通过几何反馈纠正最初的部件/状态解释，以及区分局部真实变化与全局注册错误。** 不能主张“VLM 能知道门会开”是新贡献。跨时段缺失运动过程可能让类别先验有用，也更容易导致 VLM 凭常识误判；必须允许不确定。

### 可以推翻假设的对照与数据边界

必须对照 FunREC（相同 RGB-D/内参信息）、Dynapo+固定后端、SM4RT/Flow4R、同 masks 的几何多刚体/关节拟合，以及一次性 VLM。如果只是识别门的类别就够，或 joint-fitting 一样有效，Agent 增量不成立。必须保留“柜门从未移动”和“整台柜子移动”的反例，检验是否过度套用常识。

RealFun4D/OmniFun4D/HOI4D 可检验交互和部件恢复；FunREC 主网页仍标注 code/data soon，使用前需确认可用性。3RScan 有多次场景扫描、相机、对象一致 ID 与变化变换，适合跨状态分析；其参考来自扫描重建，并非所有量都是独立测量 GT。[FunREC 项目](https://functionalscenes.github.io/)、[3RScan 官方仓库](https://github.com/WaldJohannaU/3RScan)

## 4. 不应拿来当新 gap 的例子

- 行人/车辆污染匹配，VLM 让 SAM2 去除：Dynapo 是直接 baseline，RoMo 也不是纯几何方法。
- 托盘由地面搬到叉车，VLM 判断 mobile：Contextual Mapping 已展示这个情境推理。
- 用 VLM 判断抽屉平移、门旋转：FunREC、Articulate-Anything 已覆盖。
- 发现椅子挪走后更新地图：3RScan/RIO、[Living Scenes](https://openaccess.thecvf.com/content/CVPR2024/papers/Zhu_Living_Scenes_Multi-object_Relocalization_and_Reconstruction_in_Changing_3D_Environments_CVPR_2024_paper.pdf)、SCaR-3D、[OASIS-Map](https://dynamic.robots.ox.ac.uk/projects/oasis-map/) 都是必须讨论的近邻。后两项之外本轮仅核查摘要/官方项目，不据此声称完整处理所有失败。

## 5. 当前判断

两个案例都能具体说明 VLM 的潜在作用，但都不足以单独支撑一个强新题。更可信的剩余问题是“语义假设与几何证据冲突时能否正确诊断并修正模型”，而不是“动态场景需要语义”。需要特别警惕把更好的 mask、已知 task target 或更强动态 solver 的收益误计为 Agent 理解错误的收益。
