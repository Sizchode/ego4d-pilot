# 失败证据、验证器与 benchmark：哪些结论可以被支持

调研截点：2026-10-19。本文件是文献分析，不是实验计划。核心问题是：一个 Agent 看到的“几何反馈”，是否真的能判别恢复成功？

## 1. 新近且必须纳入的四项研究

| 研究与首次 arXiv 日期 | 阅读范围 | 原文支持的事实 | 对当前题目的意义与边界 |
|---|---|---|---|
| [RealX3D](https://arxiv.org/abs/2512.23437)，2025-12-29 | v1 全文，重点 §4–5 | 包含退化/干净多视图、激光几何；相机从干净图像估计并与激光对齐。优化式 NVS 与 feed-forward pose/geometry 使用不同输入协议 | 真实退化恢复已有直接 benchmark；必须区分使用已知位姿的渲染恢复与从退化图像估计位姿 |
| [Can These Views Be One Scene? / SysCON3D](https://arxiv.org/abs/2605.18754)，2026-05-18 | v1 方法、实验、Discussion、FAQ | 神经重建支持的无参考一致性指标可能对噪声、无关场景混合给出虚假支持；提出 classical verification 指标与受控评测 | 把 VGGT/MASt3R 的输出再作为 verifier 并不天然可靠；“做一个几何验证器”也已有直接研究 |
| [MVM-IOD](https://arxiv.org/abs/2606.16638)，2026-06-15 | v1 §3–5 | 工业物体、独立扫描参考及标定参考相机；VGGT/π3 在采集分布变化下可能失败，输入旋转和宽高比调整能明显改变结果 | 除了匹配图损坏，还存在表征/分布失配；但某个数据集上的预处理 workaround 不等于一般性恢复算法 |
| [When Wider Views Fail](https://arxiv.org/abs/2609.24839)，2026-09-21 | v1 全文，尤其 §3.2、§5.3 | 固定十张图扩大轨道跨度，观察全局组装失败；仅两个 Google Earth Studio 场景，参考由 VGGT-Ω 生成 | 是失败现象证据；不能据其分数声称某模型对真实独立几何更准，也不能把跨度影响与 overlap 影响完全分开 |

上述论文均以本轮核实到的 arXiv 记录作为时间与版本依据，不把未单独核实的会议信息补成正式发表状态。

### 1.1 RealX3D：真实退化与 pose failure 不能混在同一协议里

该研究的 reference camera 来自干净图像的 COLMAP，再与 laser scan 注册；因此它有独立测量的几何，但相机参考不是逐帧独立追踪仪真值。正文分别评测已知位姿下的优化式重建，以及仅退化输入下的 feed-forward pose/geometry。另一个细节是 motion blur 通过沿轨迹渲染积分合成，不能把所有退化条件都称为直接物理实拍。[原文 §4.1–4.4、§5](https://arxiv.org/html/2512.23437v1)

分析：借用它研究恢复时，应明确允许系统读取什么；干净参考图像、参考位姿、激光几何不能在推理时悄悄成为额外输入。其 [NTIRE 2026 challenge](https://i2wm.github.io/3DRR_2026/) 主要强调低光/烟雾下恢复训练视图并进行 NVS，不能不加说明地把挑战成绩理解成相机恢复成绩。

### 1.2 SysCON3D：代理分数可能奖励“看起来有几何”

原文把神经指标拆成 backbone、residual、aggregation；只改善聚合不能完全消除 backbone 生成伪对应/伪几何造成的问题。COLMAP-based 分数提供可观察的匹配、注册、稠密支持，但作者也明确承认：真实有效场景仍可能因低纹理、反光或低 overlap 而失败，它不是普适真值。[原文 §3、§7、FAQ](https://arxiv.org/html/2605.18754v1)

分析：对于修复系统，“观测到几何支持不足”与“场景本身不可能重建”不是同一结论。把一个失败 backend 的分数当作该 backend 是否值得修复的最终判断，会形成循环。也不能把 scene-level consistency ranking 自动解释为 camera-pose correctness 或 recovery benefit。

### 1.3 MVM-IOD：输出存在不代表输出正确

参考位姿通过标定板、固定内参的 spatial resection 获得，仍有机器人重复定位误差；参考表面来自测量扫描。原文指出 feed-forward 模型会在困难输入上继续输出几何，且输入变换可显著改变结果。各方法的图像数量和分辨率不同，运行时间不能直接当作严格等预算排名。[原文 §3.2、§4](https://arxiv.org/html/2606.16638v1)

分析：这些结果支持“可靠性与失败检测值得研究”，不支持“加一个 LLM 必然有帮助”。用户不接受 hardcode，因此不能把该论文中的特定输入旋转操作写成遇到工业场景就执行的自称通用策略。

### 1.4 Wider Views：同一个 learned model 不能同时无条件当被测方法和真值

作者明确把参考称为 pseudo-reference，使用较多图像的 VGGT-Ω 结果，并承认模型偏置。预测只允许一个整体 similarity alignment，保留重复结构，这一点有利于暴露全局组装错误。[原文 §3.2、§5.3](https://arxiv.org/html/2609.24839v1)

分析：该工作对“只看局部表面质量可能漏掉全局失败”有启发；其结果还不足以证明广泛真实数据上的恢复机制或模型排序。

## 2. 原始提案的数据表需要怎样理解

| 数据源 | 可支持的研究用途 | 不能直接假设的事情 |
|---|---|---|
| [ETH3D](https://www.eth3d.net/overview) | 激光参考的几何评价；室内外多视图 | 有官方 MVS split 不代表有现成的 recovery 任务；高分辨率部分只有 13/12 train/test scenes |
| [DTU](https://roboimagedata.compute.dtu.dk/?page_id=36) | 标定相机、结构光参考、控制采集条件 | 原本的 calibrated MVS 任务不能自动等同未知外参的恢复；应隐藏待预测外参 |
| [Map-free](https://github.com/nianticlabs/map-free-reloc) | 相对位姿、有限 query 观察的定位 | 官方 single-frame / up-to-9-frame 协议禁止整段 query scan；不能直接拿全序列 SfM 结果报其官方榜单 |
| CO3D、Tanks and Temples | 原提案中的重要候选，需要按所用版本审计 reference 来源和具体 track | 本次不将它们的名称本身当作独立相机真值或恢复协议的证据；本轮部分原站/PDF 读取失败，未补写未核实细节 |

## 3. 区分四类信息

| 信息 | 例子 | 在研究中的角色 |
|---|---|---|
| 推理时可获取的测量 | 未用过的真实图像、重新估计的 pairwise correspondence | 可以提供新证据，但必须计成本 |
| 从当前模型派生的统计 | 同一组 absolute poses 推导出的闭环、用于拟合的训练残差 | 可能只是内部自洽，不能自动验证正确性 |
| 学习模型给出的先验 | 深度、语义、质量分数、不确定性 | 可帮助推断；仍须验证校准、偏置与适用范围 |
| 离线参考 | GT pose、激光表面、干净参考视图 | 用于监督或最终评价；若用于在线挑动作，应明确称 oracle |

表中是本报告的分析分类，不是某篇论文的新增方法。

## 4. 对文献评价的五项约束

1. 不把注册率直接等同正确相机比例，也不让删掉困难相机后的较低平均误差掩盖 coverage 损失。
2. 不让每个断开分量分别自由对齐，从而掩盖全局结构拼接错误；若任务允许分量输出，应单独说明评价对象。
3. 区分候选生成、诊断、工具执行、验证与失败试验的成本。不能只给最终被选中的轨迹计费。
4. 区分模型推理的 proxy feedback、独立观测验证和离线 GT。相同名称的“depth error”可能对应完全不同的参考来源。
5. 只有自然失败子集也会有选择偏差；论文结论应解释适用的失败分布，而非把特定场景结果扩展为普遍恢复能力。

这些约束解释了为什么必须先读 protocol 与方法细节，再判断一个 Agent 的改进究竟来自新推断机制、更强工具、更多计算，还是额外信息。
