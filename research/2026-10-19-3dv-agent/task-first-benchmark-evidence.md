# Task-first RGB multi-view reconstruction benchmark evidence

Checked 2026-10-19 against original papers, dataset sites, and official repositories. This note recommends an evaluation contract, not a fixed reconstruction toolkit. No experiments were run.

## Recommendation (inference)

Define the primary task first: **static, unposed RGB multi-view images → camera intrinsics/extrinsics and dense scene geometry**. Ground-truth poses, depth, scans, and evaluator feedback remain unavailable to the agent at test time. Evaluate both camera recovery and geometry reconstructed with the predicted cameras; a good depth map with wrong cameras is not a successful reconstruction.

Use the **released Depth Anything 3 Visual Geometry Benchmark protocol** as the initial reproducible main suite: ETH3D, ScanNet++, 7Scenes, HiRoom, and DTU. Its coverage follows the task—objects, indoor/outdoor scenes, real/synthetic data—and it already evaluates pose plus dense reconstruction. This is five dataset families, not a requirement to choose exactly four or to choose data that a preselected toolkit supports. Adapters may wrap any inference pipeline, including a training-free agent workflow.

Report `pose` and `recon_unposed` as primary results. Treat `recon_posed` as a separate diagnostic task with additional GT input, not as evidence that an RGB-only workflow recovered cameras. Preserve each benchmark’s native units, alignment, visibility masks, and thresholds; do not average millimetre DTU errors with metre scene errors. Pin evaluator commit, asset versions, scene IDs, and frame IDs before experiments. [Official DA3 benchmark documentation](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/main/docs/BENCHMARK.md)

|---|---|---|

| π³, July 2025 preprint; current official repository labels **ICLR 2026**, not ICCV 2025 | Camera angular evaluation: Co3Dv2/RealEstate10K; trajectory evaluation: Sintel/TUM/ScanNetv2; point maps: 7Scenes/NeuralRGBD/DTU/ETH3D. Official evaluation branch supplies deterministic sampling maps and scripts. [Evaluation instructions](https://github.com/yyfz/Pi3/tree/evaluation), [pose protocol](https://github.com/yyfz/Pi3/blob/evaluation/relpose/README.md), [point-map protocol](https://github.com/yyfz/Pi3/blob/evaluation/mv_recon/README.md) | Good bridge to contemporary baselines, but these are multiple protocols, not one interchangeable leaderboard. |
| Pi3X, 2025-12-28 | Official authors explicitly call it an **engineering update**: smoother point clouds, improved confidence, optional pose/intrinsics/depth conditioning, approximate metric scale. [Benchmark](https://github.com/facebookresearch/map-anything/blob/main/benchmarking/dense_n_view/README.md), [data processing](https://github.com/facebookresearch/map-anything/blob/main/data_processing/README.md), [paper](https://arxiv.org/abs/2509.13414) | Complementary protocol for view-count/metric geometry analysis; connected-input assumption must be disclosed. | Depth Anything 3, November 2025 | Released visual geometry suite supports camera AUC@3°/@30°, unposed and posed reconstruction, F-score and mean accuracy/completeness. ## DA3 released suite: exact scope and important caveats

The pinned DA3-BENCH registry inspected on 2026-10-20 contains **11 ETH3D scenes, 20 ScanNet++ validation scenes, all seven 7Scenes scenes, 30 HiRoom validation scenes, 22 DTU reconstruction scenes × 49 views, and 13 DTU pose scenes × 64 views**. DTU-49 is geometry-only and DTU-64 pose-only in this protocol, so it does not establish joint improvement on identical DTU samples. HiRoom counts in prose documentation have differed across releases; the immutable dataset revision and its scene registry determine the 103 executed scene/config entries. [Official released protocol](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/main/docs/BENCHMARK.md)

DA3 filters some ETH3D rotations and uses reprocessed ScanNet++ cameras. Its preprocessing therefore matters when comparing against papers using original cameras. HiRoom is synthetic, not an independently laser-scanned real-room dataset. The code supports evaluation-only use of saved predictions. [DA3 evaluator](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/main/src/depth_anything_3/bench/evaluator.py), [HiRoom adapter](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/main/src/depth_anything_3/bench/datasets/hiroom.py), [SpatialBench source-data descriptions](https://github.com/Ropedia/SpatialBench/blob/main/benchmark/README.md)

## Dataset provenance: new releases versus established benchmarks

| Dataset | Age / reference measurements | Suitability for camera + geometry claims |
|---|---|---|
| DTU MVS | **2014**, structured-light reference points, calibrated cameras, 49/64 views, lighting variations. Official SampleSet includes projections, observation masks, and evaluation code. [Dataset](https://roboimagedata.compute.dtu.dk/?page_id=36) | Strong controlled-object geometry and calibration benchmark. **Structured light**, despite DA3 README loosely calling it laser-scanned. Standard accuracy/completeness error in mm; modern protocols remain valuable. |
| ETH3D | **2017** MVS dataset; separate **2019 SLAM** benchmark. DSLR/multi-camera imagery, laser-scan geometry, registered camera parameters; scan completeness and visibility matter. [Official site](https://www.eth3d.net/), [MVS paper](https://www.eth3d.net/data/schoeps2017cvpr.pdf), [data format](https://eth3d.ethz.ch/documentation) | Strong real indoor/outdoor geometry benchmark. Specify high-resolution MVS branch, not generic “ETH3D”; distinguish native benchmark test access from recent papers’ selected evaluable scenes. |
| Tanks and Temples | **2017**, large realistic indoor/outdoor sequences with industrial-laser geometry. Public training scenes include GT; provided COLMAP models and alignment are distinct from independently measured camera truth. [Dataset](https://www.tanksandtemples.org/), [downloads](https://www.tanksandtemples.org/download/) | Useful optional large-scene dense reconstruction stress test. Do not present COLMAP reference poses as independent camera GT or assume all held-out geometry is locally accessible. |
| ScanNet++ | **ICCV 2023**, **v2 released 2024-12-20**, later 2025 assets/benchmarks. High-quality laser scans, DSLR and iPhone imagery; cameras registered to scans. [Dataset/release chronology](https://scannetpp.mlsg.cit.tum.de/scannetpp/), [documentation](https://scannetpp.mlsg.cit.tum.de/scannetpp/documentation) | Strong modern real indoor geometry source. Pin v1/v2, sensor stream, camera recalibration, and split; DA3 preprocessing and MapAnything V2 are different protocols. |
| ScanNet / ScanNetv2 | **2017 / 2018**; RGB-D sequences, camera trajectories, reconstructed surfaces. [Official project](https://github.com/ScanNet/scannet.github.io/blob/master/index.md), [code](https://github.com/ScanNet/ScanNet) | Useful trajectory/depth precedent (including π³), but do not confuse with ScanNet++ or claim independently laser-scanned geometry. |
| 7Scenes | **2013**, Kinect RGB-D; reference trajectories and TSDF models obtained through KinectFusion. Official site explicitly warns RGB/depth are uncalibrated and provides default depth intrinsics. [Dataset](https://www.microsoft.com/en-us/research/project/rgb-d-dataset-7-scenes/) | Established indoor camera/geometry benchmark with known reference-quality limits; useful coverage, weaker evidence for very fine geometry than independent scans. |
| CO3D | **2021**; real object videos, camera/depth/point-cloud annotations from reconstruction pipelines. [Dataset](https://ai.meta.com/datasets/CO3D-dataset/), [paper](https://arxiv.org/abs/2109.00512) | Widely used contemporary camera benchmark. Reconstruction-derived references are not independent scan metrology; optional camera-diversity extension rather than sole proof of geometry improvement. |
| DL3DV-10K | **CVPR 2024**, 10,510 videos; official 140-scene benchmark targets novel-view synthesis and releases COLMAP cameras. [Paper](https://openaccess.thecvf.com/content/CVPR2024/html/Ling_DL3DV-10K_A_Large-Scale_Scene_Dataset_for_Deep_Learning-based_3D_Vision_CVPR_2024_paper.html), [official repository](https://github.com/DL3DV-10K/Dataset) | Broad realistic appearance/scene diversity. The inspected release does not establish independent dense scan GT; NVS PSNR/SSIM cannot replace camera and geometry metrics. |
| MVImgNet2.0 | **2024** release/paper; expanded 520K-object multiview collection, SfM-derived cameras and reconstructed dense point clouds. [Official project](https://luyues.github.io/mvimgnet2/), [paper](https://arxiv.org/abs/2412.01430) | Recent large object source, but reconstructed annotations are not independent measured geometry. Size/newness alone does not make it a stronger primary benchmark. |

## Evaluation decisions to settle before implementation (recommendations)

1. **Joint success:** report pose AUC and dense reconstruction separately, plus per-scene paired changes. Report completion/registration fraction and failed scenes; an agent must not gain score by quietly dropping difficult images or scenes.
2. **Scale/gauge:** RGB-only reconstruction has similarity ambiguity. Declare evaluator alignment and whether metric scale is part of the claim. Keep the same alignment for all systems and distinguish camera-derived global alignment from an independent per-frame alignment that could conceal inconsistency.
3. **Fair agent comparison:** run the unassisted pipeline and agent-assisted pipeline with identical RGB inputs and explicit compute/tool-call budgets. Include a fixed search/tuning baseline to test whether reasoning improves beyond additional compute. Keep GT feedback outside the agent’s loop.
4. **Coverage follows claims:** start with the published DA3 suite; add MapAnything N-view evaluation for view-count scaling, Tanks and Temples for large-scene completeness, or CO3D for broader object-camera recovery only when making those claims. Do not add datasets merely because an adapter exists.
5. **2026 extension:** SpatialBench is useful for deterministic density-controlled comparison, but its broad suite includes dynamic/robot/driving tasks beyond static reconstruction. Its README’s point-cloud archive lists only 7Scenes, DTU, HiRoom, NRGBD, and ScanNet++; do not assume every one of its 19 sources supplies equivalent dense scan GT. [Release layout and metrics](https://github.com/Ropedia/SpatialBench)

RealX3D 2026 is being investigated separately: its posed novel-view-synthesis challenge is not by itself evidence of an immediately usable unposed joint camera/dense-geometry benchmark. Do not commit it to the main suite without verifying the required reference data and evaluation release.
