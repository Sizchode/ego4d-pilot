# 实验计划：从失败分析到修复方法

先跑 baseline → 分析失败 → 开发 toolkit → 设计 agent

目标：在固定 RGB 照片下，改善相机估计与三维表面。冻结预训练模型，允许场景内几何优化。工具集和 agent workflow 由实测失败决定，目前不预设。

## 1. 跑 baseline，建立结果档案

采用 DA3 发布的 DTU、ETH3D、ScanNet++、7Scenes、HiRoom 子集与评测代码 [S1]。先划清开发场景和最终评测场景，保存图像、场景 ID、权重与配置。

先跑 VGGT、VGGT-Ω、π³-X、MapAnything、DA3：它们从照片预测相机、深度或三维点。再跑 GGPT 等已有强修复流程，确认哪些问题已能解决。按同输入比较，保存逐场景指标、相机、深度、点云和失败日志。Ω 的复现权重访问仍待取得。

## 2. 分析反复出现的失败

在开发场景上对照原图、参考几何和跨视图证据，归纳实际错误。记录：出现在哪些模型与场景、发生率、对几何质量的影响、疑似原因，以及已有方法能否修复。区分观察到的现象与原因推断，不能确认的标“未知”。

例如墙面重影可能来自相机错位，也可能来自深度错误；需分别检查“固定深度只换相机”和“固定相机只改几何”。这是分析方法示例，并非已发现的案例。

产出一张失败清单：错误类型｜案例与频率｜影响｜已有修复的结果｜仍缺什么。按频率、影响和剩余修复空间选少数核心问题；论文里的失败只作为线索，不替代本次实测。

## 3. 针对核心失败开发 toolkit

每个工具对应一个已确认的问题，明确输入、修改对象、可用证据和验收指标。先单独运行，比较修复前后及已有强方法，同时检查准确度、完整度与退化比例。

BA / GLUEMAP 的相机优化、GGPT 的点云修复只是候选组件。是否接入、需要怎样的新工具，由上一步决定；不提前锁定工具集。先得到一套有实测修复能力的 toolkit 和固定调用流程。

## 4. 再设计 workflow，验证 Agent 增量

根据工具的适用条件、依赖顺序和失败反馈设计 workflow，再让 VLM 选择修哪里、用什么、何时重试或撤销。需要哪些图像与几何诊断，也由失败分析决定。

同初始结果、同工具和可比预算下，比较固定流程、几何指标选择器、一次性 VLM 计划、多步 VLM、无图像多步 VLM。分别检验工具选择、执行反馈和视觉信息是否有用；共享快照验收规则。

在开发集完成调整后冻结方案，最终评测全部预定场景。按各数据协议报告相机 AUC、几何准确度/完整度、Overall 或 F-score，以及失败率、退化比例和总成本。测试真值不参与调参、选动作或选结果。

若提升来自工具，就归因于工具；只有超过同工具的固定流程与几何选择器，才支持 VLM 决策的价值，进一步超过一次性计划才支持多步反馈。下一步工作是 baseline 复现与失败档案，不是先实现 agent。
